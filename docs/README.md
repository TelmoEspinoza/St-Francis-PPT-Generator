# St Francis PPT-Generator — Project Docs

Starter documentation set for a small, modern software project.

| Doc | Purpose |
|---|---|
| [01 — Product Brief](01-product-brief.md) | Why this exists, who it's for, MVP goals |
| [02 — Functional Requirements](02-functional-requirements.md) | User stories, use cases, acceptance criteria |
| [03 — Technical Design](03-technical-design.md) | Architecture, stack, component flow |
| [04 — Non-Functional Requirements](04-non-functional-requirements.md) | Performance, security, reliability targets |
| [05 — API & Data Schema](05-api-data-schema.md) | Slide schema, REST/CLI interface |
| [06 — Roadmap](06-roadmap.md) | Phased milestones |
| [adr/0001-template.md](adr/0001-template.md) | Architecture Decision Record example + reusable template |
| [07 — Test/QA Plan](07-test-qa-plan.md) | Test levels, key test cases, release checklist |

## Suggested reading order

Product Brief → Functional Requirements → Technical Design → NFR → API/Data Schema → Roadmap. Use the ADR template whenever a non-obvious technical decision needs to be recorded going forward.
